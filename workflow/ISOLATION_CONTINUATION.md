# 原目录续跑与未完成模拟处理

## 续跑

```bash
python3 workflow.py isolation-resume MODEL --name RUN --time-max 3.0681360790075956 --submit
```

- `--time-max` 是总终点的求解器代码时间；当前非宇宙学单位下，上例对应总物理时间3 Gyr。
- 不加 `--submit` 只显示计划，不提交、不查询调度器或修改参数。
- 沿用原 `RUN/output`、原主restart和MPI数，求解器使用二进制restart标志1，
  跳过converter/AGAMA。不再为续跑另建一套数据目录或复制restart。
- 只延长TimeMax；旧参数和原绑定记录保存在续跑历史中，参数版本自动登记。
- `.resume-NNN` 是小型控制文件/程序记录，不是新的快照目录。
- 原发送脚本、原IC及已有旧运行保持不动；活动作业不会重复提交。
- 同一续跑请求重复执行返回原作业；失败续跑可以用相同总终点重试。

## 处理中途数据

继续使用原命令，无需等待模拟结束：

```bash
python3 workflow.py isolation-check Fornax8001 Fornax8002 \
  --run Fornax8001=RUN1 --run Fornax8002=RUN2 --fetch
```

未完成模拟保守跳过最新一个文件，固定当次可用快照清单，只读处理这些快照。
输入视图是链接，不复制原始数据，也不伪造“模拟已完成”状态。
多个模型仍共用一个节点顺序处理；模拟可以继续写后续快照。
不同截止范围的结果独立保存，回传的文件名含运行名和快照范围，避免覆盖较早结果。
默认回传视频和CSV到本地各模型的 `isolation/`，不回传全部原始快照或逐帧图片。
常规处理不计算粒子/视频哈希，也不按持续增长的快照数反复验收旧视频。

本次没有搬动或重新提交8001/8002已有的分段续跑。那些既有分段的来源保持原记录；
后续使用上述续跑入口，才会从开始就将整个时间序列留在同一个output目录。
